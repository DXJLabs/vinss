# Public Rekber dispute arbitration

Arbitration follows the transaction rail in the original wallet-signed Rekber Agreement. `buildDisputeRekberBinding` preserves `transactionMode`, `publicRailAddress`, and `publicRekberAddress` on both setup and acceptance. The two approvals must agree. Public typed data appends `Public Rail` and `Custody Contract` to the original setup/acceptance types in the same order as frontend signing. Their values are included in both wallet signature hashes.

Challenge, attestation submission, status polling and evaluation use the binding to select the backend. Shield and legacy agreements use `NEXT_PUBLIC_BACKEND_URL`. Public agreements use `NEXT_PUBLIC_UNSHIELD_BACKEND_URL`; an absent URL fails before any fetch. Routing never follows a global UI toggle or falls back to Shield. The existing two- and three-argument evaluation APIs are retained.

Run the public backend as a separate deployment with a separate database and cloned helper configuration. Set `PUBLIC_RAIL_ADAPTER_ADDRESS` to the deployed public adapter and `ESCROW_REKBER_ADDRESS` to that adapter's actual Rekber clone. Other existing contract/indexer environment variables must reference the public deployment. The frontend adapter and Rekber values must match. `PUBLIC_RAIL_ADAPTER_ADDRESS` is optional and absent on the Shield backend.

All four dispute endpoints validate the binding's rail and deployment before custody RPC reads or database access. Public bindings fail on a backend without the adapter setting, with an unexpected adapter, or with a custody contract other than its configured Rekber. Shield bindings fail on a backend configured as public. Missing/malformed modes or deployment fields, mixed approvals, invalid signed felts and out-of-range signature limbs fail closed. Legacy agreements with no transaction mode retain their original Shield typed data and signature hashes.

Public arbitration consent challenges additionally bind the adapter and configured custody contract, alongside the existing chain ID, case commitment, custody commitment, wallet and role. This prevents reuse of public arbitration consent on another clone. Shield challenge formats are unchanged. Custody reads, valuation reads and resolver execution use the same configured Rekber. Original mutable fulfillment/revision chain heads remain authenticated by the Agreement signatures; they are deliberately not compared against advanced live cursors.

The case commitment still identifies the exact canonical consented evidence; it is not a public calldata payload. Database decision/attestation identities remain network and case scoped within the required separate deployment database. Resolver authorization sends only custody/decision commitments and exact amounts to the configured contract. Accepted terms, evidence text, room secrets and preimages are never added to arbitration calldata. Arbitration's existing explicit consent boundary is retained: the dedicated backend receives only the evidence case the parties submit.

Verification covers exact frontend/backend setup and acceptance typed-data and message-hash parity, legacy Shield behavior, public-only consent deployment/chain separation, all frontend request routes, missing-backend failure, and all four backend handlers with matching public custody and pre-RPC cross-deployment rejection. RPC wallet validity and persistence are fixtures in runtime tests; these are not claims of deployment or live transactions.
