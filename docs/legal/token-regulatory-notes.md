# VINSS Token Regulatory Notes

**Status:** Future-design issue spotting only  
**Last reviewed:** 2026-08-30  
**Not legal advice.**

VINSS token is not required for the current product business model.

This file exists so token decisions do not accidentally become product promises before legal review.

---

# 1. Keep Four Layers Separate

```text
Points
        ≠
Settlement SBT
        ≠
VINSS token
        ≠
DXJ token / asset
```

And:

```text
product fee revenue
        ≠
token sale proceeds.
```

# 3. Token Labels Do Not Decide Legal Status

Do not assume:

```text
"utility token"
```

means:

```text
not regulated.
```

Legal analysis can depend on:

```text
rights;
economics;
marketing;
sale structure;
expectations;
redemption;
management efforts;
secondary trading;
jurisdiction.
```

# 4. EU / MiCA

MiCA creates a regulatory framework for crypto-asset offerings and service providers.

Official regulation:

https://eur-lex.europa.eu/eli/reg/2023/1114/oj/eng

Before any EU-directed VINSS token offer, determine:

```text
token classification;
white-paper / offer obligations;
issuer structure;
marketing rules;
CASP involvement;
whether another EU financial-services regime applies instead.
```

---

# 5. United States

U.S. crypto-asset securities regulation remains highly fact-specific and is actively evolving.

The SEC maintains a Crypto Task Force focused on application of federal securities laws and policy for crypto assets.

Current official hub:

https://www.sec.gov/securities-topics/crypto-task-force

Before sale/distribution to U.S. persons, obtain a fresh memo addressing:

```text
security status;
offering registration/exemption;
marketing;
airdrop/reward distribution;
secondary trading;
staking/locking;
VINSS → DXJ rights.
```

Do not rely on an old crypto legal memo for a later token design.

---

# 6. UK Financial Promotion

The FCA states that UK cryptoasset financial-promotion rules can apply to marketing to UK consumers.

Official source:

https://www.fca.org.uk/firms/cryptoassets/who-needs-register

Token marketing should therefore be jurisdiction-controlled.

# 8. SBT

Settlement SBT should primarily represent:

```text
successful settlement evidence / reputation.
```

Avoid marketing it as:

```text
investment;
yield-bearing NFT;
guaranteed financial value.
```

Any economic utility added later must be re-reviewed.

---

# 9. Presale

A presale is not ordinary product revenue.

Before presale:

```text
entity structure;
jurisdiction restrictions;
token classification;
sale terms;
KYC/AML where required;
sanctions;
investor eligibility;
vesting;
tax/accounting;
consumer/investor disclosures;
custody;
treasury controls.
```

must be reviewed.

---

# 10. VINSS → DXJ

Current future-design constraint:

```text
optional;
epoch-based;
hard-capped DXJ pool;
variable effective ratio;
no fixed permanent redemption;
VINSS burned after successful conversion.
```

This economic design reduces unlimited-liability risk but does **not** answer legal classification.

A conversion right could itself become a material token right.

It requires dedicated counsel review before announcement.

---

fixed DXJ redemption;
revenue share;
dividend;
risk-free yield;
guaranteed buyback.

# 12. Token Launch Gate

Do not launch token because:

```text
mainnet is live;
hackathon is finished;
Points exist;
community asks.
```

Require:

```text
product usage;
clear utility;
tokenomics stress test;
anti-farming;
entity structure;
tax review;
jurisdiction matrix;
AML/sanctions plan;
securities/crypto-asset counsel;
sale/distribution documentation.
```

A valid outcome is:

```text
delay token.
```
